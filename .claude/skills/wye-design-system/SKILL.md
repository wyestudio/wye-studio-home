여기서 임의 수치를 한 번 쓰면, 다음 사람이 그걸 보고 또 쓴다. 척도는 그렇게 흩어졌다.

## 이 중 하나라도 하면 이 문서를 먼저 읽는다

- 사용자가 **"좀 작게 / 크게 / 넓혀 / 붙여 / 연하게 / 진하게"** 라고 말한다
- `className` 에 `text-` · `p-` · `m-` · `gap-` · `rounded-` · `max-w-` 를 새로 적거나 고친다
- `style={{ fontSize … }}` · `text-[13px]` · `p-[7px]` 처럼 **대괄호로 수치를 박는다**
- `src/app/globals.css` 의 `@theme` 블록을 건드린다

---

## 규칙은 하나다 — **단계에서 고른다**

"조금 줄여 달라" 는 **한 단계 내려 달라**는 뜻이다. 13px 을 12px 로 깎는 게 아니라
`text-label` 을 `text-micro` 로 바꾸는 것이다. 중간값을 새로 만들지 않는다.

**단계를 벗어나야 할 것 같으면 그건 보통 배치 문제다.** 글자를 줄일 게 아니라 칸을
넓히거나, 줄 수를 줄이거나, 다른 자리로 옮겨야 한다.

---

## 글자 — 크기가 아니라 **역할**로 고른다

정의는 `src/app/globals.css` 의 `@theme` 에 있다. 거기 주석이 원본이고, 아래는 요약이다.

| 토큰 | 쓰는 자리 |
|---|---|
| `text-display` | 메인 히어로, 단체 예약 H1 |
| `text-h1` | 페이지 제목 |
| `text-h2` | 섹션 제목 — H1 보다 반드시 작게 |
| `text-h3` | 카드 제목 · 시놉시스 |
| `text-body` | **설명문 전부** |
| `text-body-sm` | 각주 · 보조 안내 |
| `text-label` | 입력 라벨 · 탭 · 날짜 |
| `text-micro` | 배지 · 영문 섹션 라벨 — **이보다 작게 쓰지 않는다** |
| `text-input` | 입력칸 전용. 16px 미만이면 아이폰이 포커스 때 화면을 확대한다 |

⚠️ **`sm:` · `lg:` 로 크기 사슬을 만들지 않는다.** 토큰이 `clamp()` 라 한 클래스가
   모바일↔데스크톱을 다 맡는다. 사슬을 쓰면 모바일이 기준 아래로 내려간다 —
   진단에서 가장 많이 깎인 항목이 그것이었다(설명문 12px · 배지 9px · 입력칸 14px).

⚠️ **보기에 커 보인다고 역할을 바꾸지 않는다.** 2026-10-09 에 상세의 스펙을
   "한 단계씩" 내렸다가 `설명문 → text-body-sm`, `라벨 → text-micro` 가 되어
   모바일에서 너무 작아졌고 되돌렸다. 커 보이면 **글자가 아니라 칸을 줄인다.**

⚠️ 글자가 아닌 것(이모지·아이콘)에는 쓰지 않는다. 역할 이름이 안 맞는다.

## 굵기 — 셋뿐이다

`font-normal`(본문) · `font-semibold`(강조·라벨·카드 제목) · `font-extrabold`(페이지·섹션 제목).
**`font-bold`(700) · `font-medium`(500) · `font-black`(900) 을 새로 쓰지 않는다**
← 700 이 600 과 800 사이에서 역할이 겹쳐 "강조" 와 "제목" 의 경계를 흐렸다.

## 면과 선 — 밝기가 아니라 **역할**이다

`bg-fill-subtle` / `bg-fill` / `bg-fill-strong`, `border-line-subtle` / `border-line` / `border-line-strong`.

⚠️ **`bg-white/[0.04]` · `border-white/30` 처럼 투명도를 직접 적지 않는다.**
⚠️ `fill-strong` 과 `line-strong` 은 "더 진한 색" 이 아니라 **hover·선택 상태**다.
   밝기순으로 바꿔치우면 눌렀을 때 반응이 사라진다(달력 · 회차 선택 · 진행바).

## 둥글기 — 셋뿐이다

`rounded-md`(배지·칩) · `rounded-lg`(버튼·입력칸·카드) · `rounded-xl`(큰 패널).
`rounded-full` 은 크기가 아니라 모양이라 따로다(알약·원).
**`rounded`(4px) · `rounded-2xl`(16px) 을 새로 쓰지 않는다** ← 어드민 4px / 공개 8px 로
시스템이 두 벌로 갈려 있었다.
`rounded-none` 은 도트 게임 느낌을 내는 자리에서만 의도적으로 쓴다(테마 상세의 모드 창).

## 가운데 틀 폭

`max-w-5xl`(사이트 틀) · `max-w-4xl`(달력) · `max-w-3xl`(읽는 글·상세 블록) ·
`max-w-2xl`(신청 폼) · `max-w-md`(입력 두세 칸).
⚠️ **한 페이지 안에서 블록마다 다른 폭을 쓰지 않는다** ← 스크롤하면 본문 좌우 끝이
계단처럼 움직인다.

## 여백 — Tailwind 눈금에서 한 칸씩

간격은 따로 토큰을 만들지 않았다. **Tailwind 기본 눈금(4px)** 이 척도다.
넓혀 달라면 `pt-5 → pt-6`, 더 넓히면 `pt-8` 로 **칸을 옮긴다.**
`p-[7px]` · `gap-[13px]` 처럼 대괄호로 박지 않는다.

예외는 **광학 보정**뿐이다 — 큰 숫자 옆 글자의 `-ml-1.5` 처럼 글꼴 때문에 생기는
빈틈을 메우는 자리. 그런 값에는 **왜 그 수치인지 주석을 붙인다.**

## 어드민도 포함이다

2026-10-06 에 공개 화면 397줄 · 어드민 737줄을 전부 이 토큰으로 옮겼다.
"어드민은 정보 밀도가 목적이라 기준이 다르다" 고 적어 뒀던 적이 있지만, 밀도는
척도 안의 `text-micro`(12px) · `text-label`(13px) 로 표현된다. 두 벌을 두면 새 화면을
쓸 때마다 어느 쪽인지 따져야 한다.

## 척도 밖에 일부러 남긴 곳

- **가격표의 금액 숫자**(`PriceTable`) — 가장 가까운 토큰이 모바일에서 6px 커지는데,
  거기는 금액이 잘렸던 자리다.

여기 말고 새로 예외를 만들려면 **왜 토큰으로 안 되는지 주석에 적는다.**

## 고치고 나면 확인한다

브라우저로 **모바일 폭(390)과 데스크톱 폭(1280) 둘 다** 본다. 글자가 칸 밖으로
넘치는지(`scrollWidth > clientWidth`)와 가로 스크롤이 생겼는지를 같이 잰다 —
줄인 쪽은 눈으로 잘 안 보이고, 늘린 쪽은 잘린다.
