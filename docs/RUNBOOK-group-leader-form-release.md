# 운영 반영 안내 — 단체 모임장 신청서 · 슬랙 새 채널

단체 예약의 **모임장 신청서**(공개 폼 `/f/<코드>`)를 운영 서버에 올리는 사람이 따라 하는 순서다.
코드는 이 저장소에 있고, 여기에는 **코드 밖에서 사람이 해야 하는 일**(DB · 슬랙 · 환경변수 · 확인)만 적는다.

> 순서가 중요하다. **DB → 슬랙 채널 · 환경변수 → 코드 배포 → 확인.**
> DB 보다 코드가 먼저 올라가면 단체 상세 화면과 폼이 오류를 낸다.

## 0. 한눈에

| 무엇 | 값 |
|---|---|
| 슬랙 새 채널 | `#단체-모임장-신청서` |
| 환경변수 이름 | `SLACK_GROUP_LEADER_FORM_WEBHOOK_URL` |
| 환경변수 값 | 그 채널의 Incoming Webhook 주소 (`https://hooks.slack.com/services/…` 로 시작) |
| 넣는 곳 | Vercel 운영 프로젝트 › Settings › Environment Variables › **Production** |
| 넣은 뒤 | **재배포**해야 적용된다 |

## 1. DB — 마이그레이션 (코드 배포 전에)

`wye-db-release` 스킬의 절차대로, 테스트 DB 에서 확인한 것을 운영 DB 에 **아래 순서로** 적용한다.
이미 적용된 것은 건너뛴다(`supabase_migrations.schema_migrations` 로 확인).

1. `20261127024910_admin_todos.sql`
2. `20261127040548_group_booking_admin.sql`
3. `20261127052421_group_forms.sql`
4. `20261127055357_group_leader_form.sql` ← 모임장 신청서
5. `20261127062909_group_teams.sql` ← 팀 편성 · 명찰 상태(참가자 · 팀 편성 탭을 같이 올릴 때)
6. `20261127064032_admin_tools_bucket.sql` ← 관리자 도구 파일용 비공개 버킷(명찰 제작기를 같이 올릴 때 — 아래 「명찰 제작기 파일 올리기」 도 해야 한다)
7. `20261127065609_group_reports.sql` ← 플레이 리포트 내용(리포트 탭을 같이 올릴 때 — 아래 「리포트 틀 파일 올리기」 도 해야 한다)
8. `20261127073107_group_form_templates.sql` ← 설문 양식 버전 표 · 참가자 제출 함수 v2(단체 도구 › 설문 양식을 같이 올릴 때.
   **이 마이그레이션 없이 코드만 올리면 참가자 사전 설문 제출이 실패한다** — 제출이 새 함수(v2)를 부른다.
   폼 화면 자체는 표를 못 읽어도 기본 양식으로 열린다)

적용 뒤 확인

- 새 표 `group_leader_responses` 에 RLS 가 켜져 있고 정책이 없다(= 공개 키로는 닿지 못한다).
- 새 함수 5개(`submit_group_leader_form` · `verify_group_leader_phone` · `request_group_leader_edit` ·
  `admin_set_group_contact` · `admin_apply_group_leader_name`)의 실행 권한이 `service_role` 에만 있다.
- Supabase 보안 어드바이저에 이 표 · 함수에 대한 새 경고가 없다.

## 2. 슬랙 — 새 채널과 웹훅

모임장 신청서 알림은 기존 「단체 예약 견적 신청」 알림과 **다른 채널**로 간다. 견적 신청은 처음 들어온 문의,
이쪽은 그 뒤에 모임장이 써서 낸 신청서다.

1. 슬랙에서 채널을 만든다: **`#단체-모임장-신청서`**
   (기존 알림 채널이 영문 이름이라 맞추고 싶다면 `#group-leader-form-notification` 처럼 지어도 된다.
   채널 이름은 코드에 들어 있지 않다 — 웹훅 주소만 맞으면 된다.)
2. 그 채널에 **Incoming Webhook** 을 하나 만든다.
   기존 알림 채널들에 쓰는 것과 같은 슬랙 앱에서 「Add New Webhook to Workspace」 → 방금 만든 채널을 고른다.
3. 만들어진 주소(`https://hooks.slack.com/services/…`)를 복사한다.
   **이 주소는 비밀 값이다.** 저장소 · 채팅 · 문서에 적지 않는다. 아는 사람은 누구나 그 채널에 글을 올릴 수 있다.

## 3. Vercel — 환경변수

1. Vercel › **운영 프로젝트**(운영 도메인이 붙은 프로젝트) › Settings › Environment Variables
2. 추가
   - Key: `SLACK_GROUP_LEADER_FORM_WEBHOOK_URL`
   - Value: 2번에서 복사한 웹훅 주소 **전체**
   - Environment: **Production** 만 체크
3. 저장한 뒤 **재배포**한다(환경변수는 새 배포부터 적용된다).

주의

- **값 칸에 변수 이름을 넣지 않는다.** 2026-10-02 에 값 칸에 `SLACK_GROUP_BOOKING_WEBHOOK_URL` 이라는 글자가 들어가
  알림이 조용히 안 온 적이 있다. 값은 반드시 `https://hooks.slack.com/` 으로 시작해야 한다 — 아니면 코드가 무시하고 로그에 남긴다.
- **테스트 프로젝트(`wye-studio-home-test`)에는 넣지 않는다.** 테스트 서버에서는 이 알림을 아예 보내지 않는다
  (테스트로 낸 신청서가 운영 채널에 쌓이지 않게 — 단체 견적 알림과 같은 규칙).
- 이 변수를 **빠뜨려도 알림은 사라지지 않는다.** 비어 있으면 단체 견적 채널(`SLACK_GROUP_BOOKING_WEBHOOK_URL`)로,
  그것도 없으면 기본 채널(`SLACK_WEBHOOK_URL`)로 간다. 제목이 `[단체 신청서]` 로 시작해 견적 신청(`[단체예약]`)과 구분된다.
  다만 채널이 섞이므로 넣는 것이 맞다.

## 4. 코드 배포

`develop` 에서 확인이 끝난 것을 대표님이 "운영에 올려줘" 라고 했을 때 `main` 으로 올린다(저장소 `CLAUDE.md`).

## 5. 배포 뒤 확인 (운영에서)

1. 관리자 › 단체 예약 › 아무 단체(시험용이 좋다) › 「설문 · 문자」 탭 → 「모임장용 신청서」 링크가 보인다.
2. 그 링크를 **휴대폰**으로 열어 끝까지 내 본다.
   - 확인 화면에 견적에서 받은 값이 보이고, 담당자는 가린 값(`김*윤`)으로만 보인다.
   - 제출하면 「신청서를 잘 받았어요」.
3. 슬랙 `#단체-모임장-신청서` 에 알림이 온다.
   - `📝 [단체 신청서] 신청서 도착 — 모임명` · 행사 · 인원 · 팀 편성 · 확인할 내용 · 관리자 주소
   - **이름과 연락처는 들어 있지 않아야 한다.**
4. 같은 링크를 다시 열면 휴대폰 번호 끝 4자리를 묻는다. 맞게 넣으면 낸 내용이 보이고, 「수정 요청」 을 보내면
   슬랙에 `✏️ [단체 신청서] 모임장 수정 요청` 이 오고 관리자 홈의 오늘 할 일에 뜬다.
5. 관리자 › 그 단체 › 개요의 「모임장 신청서」 카드에 요약 · 수정 요청 · 「신청서와 다른 내용」 이 보인다.
6. 시험으로 낸 신청서는 시험용 단체째로 정리한다.

알림이 안 오면

- Vercel 함수 로그에서 `[slack]` 으로 시작하는 줄을 찾는다.
  - `…의 값이 슬랙 웹훅 주소가 아니라 무시합니다` → 값 칸을 다시 확인한다.
  - `쓸 수 있는 웹훅이 없어 … 건너뜁니다` → 변수가 Production 에 들어갔는지, 재배포했는지 확인한다.
  - `전송 실패: 404` → 웹훅이 지워졌거나 주소가 잘렸다. 다시 만든다.
- 알림이 실패해도 **신청서 저장은 끝난 것**이다. 관리자 홈과 단체 상세에서 확인할 수 있다.

## 명찰 제작기 파일 올리기 (참가자 탭의 「명찰 만들기」)

명찰 제작기는 45MB 짜리 단일 HTML 이라 저장소에 없다(공개 저장소다). **코드 배포와 따로**, Supabase 비공개 버킷
`admin-tools` 에 사람이 올려야 한다. 안 올리면 「명찰 만들기」 가 "파일을 찾지 못했습니다" 라고 알려준다(다른 화면은 멀쩡하다).

1. 6번 마이그레이션(`admin_tools_bucket`)을 운영 DB 에 적용한다 — 버킷이 생긴다(비공개 · 정책 없음 · 50MB).
2. 대표님께 제작기 원본(`강아지_명찰_제작기.html`)을 받는다.
3. 원본에 **명단 받는 부분만** 넣는다(디자인 · 템플릿 · 폰트는 건드리지 않는다).

   ```bash
   node scripts/admin-tools/patch-nametag-maker.mjs <원본.html> /tmp/nametag-maker.html
   ```

   "넣을 자리를 찾지 못했다" 고 멈추면 제작기 구조가 바뀐 것이다 — 올리지 말고 개발자에게 알린다.
4. 운영 프로젝트에 올린다. 서비스 키는 **환경변수로만** 넘긴다(명령줄에 적지 않는다 — 셸 기록에 남는다).

   ```bash
   SUPABASE_URL=<운영 프로젝트 주소> SUPABASE_SERVICE_ROLE_KEY=<운영 서비스 키> \
     node scripts/admin-tools/upload-admin-tool.mjs /tmp/nametag-maker.html nametag-maker.html
   ```

   스크립트가 "올리는 곳: ○○○.supabase.co" 를 찍는다 — **운영 프로젝트가 맞는지 보고** 진행한다.
5. 확인
   - 로그인 없이 받아지지 않는다: `<프로젝트 주소>/storage/v1/object/public/admin-tools/nametag-maker.html` 을 브라우저로 열면 오류(400)가 나와야 한다.
   - 관리자 › 단체 › 참가자 탭 › 「명찰 만들기」 → 설문 인원만큼 명찰이 생기고 방수에 맞는 색이 쓰인다.
   - 「벡터 PDF 저장」 을 눌러 A4 가로로 **명찰만** 인쇄되는지 본다(관리자 화면의 버튼 줄이 같이 찍히면 안 된다).
   - 닉네임을 하나 고치고 닫았다 다시 열면 고친 내용이 남아 있다.
6. `/tmp/nametag-maker.html` 을 지운다.

제작기를 새 판으로 바꿀 때는 3~5 를 다시 하면 된다. 관리자 브라우저는 파일이 바뀐 것을 알고 다시 받는다.

## 리포트 틀 파일 올리기 (리포트 탭의 「리포트 만들기」)

플레이 리포트 틀도 저장소에 없다. 명찰 제작기와 같은 버킷(`admin-tools`)에 `play-report.html` 로 올린다.

1. 6 · 7번 마이그레이션을 운영 DB 에 적용한다.
2. 대표님께 리포트 틀 원본(HTML)을 받는다. **원본에는 실제 단체의 사진 · 팀명이 들어 있을 수 있다** — 그대로 올리지 않는다.
3. 저장돼 있던 내용을 비우고 값 주고받는 부분을 넣는다.

   ```bash
   node scripts/admin-tools/patch-play-report.mjs <원본.html> /tmp/play-report.html
   ```

   결과가 60KB 안팎이어야 한다. 스크립트는 사진이 남아 있으면 파일을 쓰지 않고 멈춘다.
4. 운영 프로젝트에 올린다(서비스 키는 환경변수로만).

   ```bash
   SUPABASE_URL=<운영 프로젝트 주소> SUPABASE_SERVICE_ROLE_KEY=<운영 서비스 키> \
     node scripts/admin-tools/upload-admin-tool.mjs /tmp/play-report.html play-report.html
   ```
5. 확인
   - 관리자 › 단체 › 리포트 탭 › 「리포트 만들기」 → 일시 · 모임명 · 인원 · 팀이 채워져 열린다.
   - 「내용 저장」 뒤 닫았다 다시 열면 글자 · 팀 · 점수가 남아 있다. **사진은 남지 않는다**(일부러 저장하지 않는다).
   - 리포트 안의 [HTML 저장] · [PDF / 인쇄] 가 동작한다.
6. `/tmp/play-report.html` 을 지운다.

## 되돌리기

- 환경변수만 지우고 재배포하면 알림은 단체 견적 채널로 돌아간다.
- DB 를 되돌려야 하면 `20261127055357_group_leader_form.sql` 머리말의 「되돌리기」 를 따른다(받은 신청서가 지워진다 — 먼저 백업).
